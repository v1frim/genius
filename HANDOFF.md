# HANDOFF — «Genius», тренажер геніальності

Стан на **2026-06-29**. Усе описане нижче змерджено в `main` і задеплоєно.

> **Як читати цей файл:** це повний контекст проєкту. Нова сесія має прочитати його
> цілком — і можна одразу продовжувати роботу без додаткових пояснень від користувача.

## Що це

Особистий сайт-тренажер користувача (v1frim) для щоденного розвитку: увага, швидкочитання,
друк, дикція, усний рахунок, пам'ять, медитація + трекер цілей і щоденних задач.
Повністю статичний (HTML/CSS/JS без збірки), працює офлайн, дані в localStorage.

- **Репозиторій**: https://github.com/v1frim/genius
- **Сайт**: https://v1frim.github.io/genius/ (GitHub Pages, deploy from branch `main`, root `/`)
- **Мова UI**: українська. Усі коміти/комунікація — українською.

### 1. Інтеграція з Oxford 1000 (англійська) — `js/oxford.js`
Окремий сайт користувача `v1frim.github.io/Oxford_1000/` (інший репозиторій, але **той самий
origin** `v1frim.github.io` → спільний localStorage). `App.oxford` читає його ключі й рахує ту
саму шкалу «планів», що й термометр там:
- ключі: `oxford_days_v1` (games/день), `oxford_duolingo_v1` (сесії/день), `oxford_lingohut_v1`
  (`{урок: дата}`). Бали за день = games + duo + Σ(урок≤35?1:2, якщо зараховано того дня).
  **1 план = 4 бали.** «Сьогодні» — в UTC (як термометр); тиждень — пн..нд (`store.mondayStr`).
- API: `pointsToday / plansToday / pointsThisWeek / plansThisWeek / pointsForDate / hasData`.
- У дашборді (`TASK_TRACKERS`) додано авто-задачі: щоденна `engPlanDay` (done при ≥2 планах,
  бейдж `X/2`) і щотижнева `engPlanWeek` (done при ≥14, бейдж `X/14`). Лінк задач — на Oxford.
  Працює лише в одному браузері/пристрої (спільне сховище). Без даних Oxford → 0, без помилок.

### 2. Прибрано щоденну задачу «Журнал Шерлока» (`observe`)
З `defaultTasks`; ціль `sherlock` лишилась. Прибирається і зі збереженого стану (міграція).

### 3. Міграції списку задач — `store.js → migrateTasks()` (версія `state.engPlanV`, зараз **v3**)
Одноразові, самовиправні. Прибирають старий ручний `eng` і попередній дворядковий варіант
(`engPlan1/2`), додають `engPlanDay`+`engPlanWeek`, прибирають `observe`. Викликається з `load()`

### 4. PWA — встановлюваний застосунок + офлайн
`manifest.webmanifest` + `sw.js` (service worker, стратегія **network-first**: онлайн завжди
свіжо, кеш лише офлайн-резерв) + іконки + apple-теги в `<head>` + реєстрація SW в кінці index.html.
**`VERSION` у sw.js бампати при зміні набору `ASSETS`** (зараз `genius-cache-v10`).
Уроки про **iOS** (важливо!): у встановленому PWA сторонні скрипти з gstatic НЕ вантажились →
Firebase SDK **самохостимо** в `js/vendor/`. Видалення іконки НЕ чистить SW/кеш; очищення
«Вебданих» Safari теж НЕ чіпає сховище standalone-PWA (вони РОЗДІЛЕНІ). Іконку/назву на робочому
столі iOS «запам'ятовує» при додаванні — щоб змінити, треба видалити й заново додати ярлик.

### 5. Хмарна синхронізація між пристроями — `js/sync.js` (Firebase)
- **Проєкт Firebase: `genius-11387`** (акаунт vovabestintheworld@gmail.com, тариф Spark/безкоштовний).
  У консолі вже зроблено: Firestore (Production, локація `eur3`), Auth → Google, Authorized domains
  + `v1frim.github.io`. Правила: доступ лише до `users/{uid}` де `request.auth.uid == uid`.
  `firebaseConfig` зашитий у `sync.js` (apiKey — не секрет; захист правилами + Auth).
- Документ `users/{uid}` = `{ data: JSON(весь стан), client, ts }`. Перше з'єднання — **merge**
  (records union за `ts`, taskHistory за датами, timeByDay/twister — max; редаговані поля з
  «багатшого» за записами боку → захист від втрат за будь-якого порядку входу). Далі —
  **last-write-wins у реальному часі** (`onSnapshot`). Захист від циклів: прапор `applyingRemote`.
  Дебаунс пуша 800 мс. `App.sync.mergeStates` відкрито для тестів.
- **Вхід — `signInWithPopup`** (КРИТИЧНО для iOS PWA: повний редірект ламав завантаження Firebase
  на поверненні; попап тримає сторінку). **Self-heal**: якщо `firebase` не визначено — sync.js
  динамічно дотягує `js/vendor/firebase-*-compat.js` і тоді ініціалізує (`init→loadFirebaseScripts→realInit`).
- UI у «Дані» (`settings.js`): картка «☁️ Синхронізація між пристроями» — вхід/вихід Google + стан
  (`синхронізовано ✓`). `App.rerender` (=navigate, виставлено в app.js) перемальовує екран після
  прийому хмари.
- **Тимчасова діагностична позначка «(складання N)»** у заголовку картки (зараз **6**) — лишена,
  щоб ловити баги оновлення PWA на iOS. **TODO: прибрати**, коли користувач підтвердить стабільність.

у app.js. `App.modules.<id>` — об'єкт модуля; деякі експортують хелпери (напр.
`dashboard.syncAutoTasks`, `dashboard.todayPct`, `dashboard.calcStreak`, `reading.bestTestWpm`).

## Ключові механіки

- **ЗІГРАНИЙ час за сьогодні** (НЕ присутність — користувач відмовився від presence-обліку):
  `store.timeByDay[date][sectionId]=ms`; модулі викликають `App.store.addTime(розділ, ms)` У
  МОМЕНТ завершення гри/сесії з реальною тривалістю. Роутер малює бейдж `#sectionTime` (top-right,
  ховається на не-тренажерах — `TRAINER_IDS` у app.js) і суму в сайдбарі `#totalTime`, оновлення
  ~1.5 с. Зберігається в localStorage + на visibilitychange/beforeunload. УВАГА для тестів: через
  beforeunload-save шаблон «правити localStorage напряму + reload» НЕ працює — став стан через
  `App.store.state.*` + `App.store.save()`, навігуй через `location.hash`.
- **store.rollover()**: при зміні дати — вчорашні щоденні задачі → `taskHistory` (pct), чекбокси
  скидаються; щотижневі — по понеділках. Викликається при кожній навігації (app.js).
- **АВТОЗАРАХУВАННЯ задач** (НОВЕ): `dashboard.js` має `TASK_TRACKERS` (ключ = id СТАНДАРТНОЇ
  задачі), кожен повертає `{done, sub}` за сьогоднішніми/тижневими записами/часом. `taskAuto(t)`/
  `taskDone(t)` рахують стан наживо; `syncAutoTasks()` пише виконане в `taskState` (щоб стрік/
  історія були правильні) — викликається з app.js `navigate()` після rollover і на рендері
  дашборду. У рядку задачі: якщо є трекер — чекбокс disabled + бейдж «авто ✓ / авто 2/3»; без
  трекера — звичайний ручний чекбокс. Трекери (за id): `schulte` (3 ігри 5×5 сьогодні), `rsvp`
  (10 хв reading), `typing` (3 записи source=ua), `twisters` (twisterByDay≥5), `arith` (1 запис
  s60), `memory` (1 digitSpan), `med` (15 хв meditation); тижневі: `rtest` (reading kind=test),
  `longmed` (meditation ≥45 хв). Ручні: шахи, дихання, харизма, журнал, книга, спорт, англ.
- **Стрік**: день зараховано при ≥70% щоденних задач (PASS_PCT у dashboard.js); todayPct рахує
  через taskDone (враховує автозадачі).
- **Цілі з auto**: рекорди підтягуються (reading test wpm, typing cpm, meditation count/max,
  digitSpan, visualMemory). `autoMode:"max"` → max(base, авто); `"count"` → base+кількість.
  RSVP-записи НЕ впливають на рекорд читання (поле `wpm` лише в kind:"test"; у RSVP — `avgWpm`).
- **App.primaryAction**: модуль реєструє функцію → глобальний Space її викликає. Скидається
  роутером при навігації. Tab/Shift+Tab — перемикання розділів.

## Специфічні рішення в модулях (з урахуванням змін цієї сесії)

- **Шульте** (`schulte.js`): сітка до 620px, око-якір у центрі на непарних. Оцінка часу
  ПЕРЕКАЛІБРОВАНА: поріг «феноменально» `eliteSec(size)=size⁴/32` (час на клітинку РОСТЕ з
  розміром — більша таблиця складніша), решта тірів — `×1.5/2.25/3.25` (`evalSec`, `TIER_MULT`).
  Малі сітки суворіші (3×3 феном ~3 с), великі поблажливіші (7×7 феном ~75 с, середньо ~244).
  Марафон 3×3→7×7 оцінюється сумою порогів (`MARATHON_ELITE`), кожна гра — окремий запис {mar:true}.
  У HUD (ліва колонка) під часом — блок `.schulte-records`: рекорди ВСІХ розмірів списком
  (`bestAnyMode(size)` — найкращий час будь-якого режиму), поточний розмір підсвічено жовтим;
  оновлюється в `updateInfo()` (працює і в марафоні). Підсвітка рекордних ігор у таблиці результатів
  (recordSet, running-best). Розміри — Shift'ами (лівий наступний/правий попередній).
- **Швидкочитання (RSVP)** (`reading.js`): джерела «Художні» (з proseExcerpts) + «Вікіпедія»
  (REST random/summary, мокати в тестах). Слова по центру (ORP — опція). Квіз 3 питання різного
  стилю (пізнавання, cloze, дійова особа/properNouns). «Адаптація темпу» (pref rsvp.adapt). Тест
  швидкості (5 текстів з питаннями) — лише він дає рекорд (kind:"test"). У «Результатах» є картка
  «найкращий RSVP-темп» (max avgWpm — м'який індикатор; рекорд тесту окремо).
  **Нове джерело «📚 Зв'язні»** (`RSVP_SOURCES`/`startPassages`): раунд = один цілий текст із
  `App.data.passages` під довжину (бін за словами), з авто-квізом — без склейки уривків.
- **Клавотренажер (Друк)** (`typing.js`): друк «крізь помилки», нормалізація ґ↔г, тире, апострофи,
  лапки. Введення через keydown на прихованому input. Таймер на паузі при блюрі (accumMs+runStart;
  читати elapsedMs ДО finished=true). `MAX_CPM=1500` — захист від зіпсованих значень (НЕ зберігати
  cpm>1500); store.load() одноразово чистить старі такі записи (був баг таймера — 2653 зн/хв).
  Запис зберігає `length` (s/m/l). Після фінішу фокус на кнопці «ЩЕ РАЗ» → Space/Enter запускають
  наступний (blur-guard лишає текст чітким). Картка «🏆 Рекорди за режимами» — матриця best по
  джерелу×довжині (для старих записів довжина з `chars`; custom — без розбивки).
  **Нове джерело «📚 Зв'язні тексти»**: `buildText` повертає ОДИН цілий текст із
  `App.data.passages` (бін за `targetChars`), без перемішування й склейки речень.
- **Скоромовки** (`twisters.js`): **381 у колекції** (винесена в `js/data.twisters.js`) + генератор з **15 алітераційних банків** (по
  літері; кожен банк — імена/прикметники/дієслова/об'єкти/місця на ту саму літеру; 3 шаблони). Це
  НЕ ШІ і НЕ вибірка з колекції — процедурна генерація однолітерних речень. Кнопка «✓ ПРОЧИТАВ ×5».
  Час: рахується лише поки вкладка активна (пауза на visibilitychange; накопичення activeMs),
  стеля 2 хв/скоромовку; «Пропустити» час не додає. cleanup знімає visibilitychange-лісенер.
  **Гарячі клавіші: Enter = «Прочитав ×5», Space = «Пропустити»** (keydown на document;
  `preventDefault` гасить подвійне спрацювання при кнопці у фокусі; знімається в cleanup).
- **Арифметика** (`arithmetic.js`): 5 рівнів, операції +−×÷ (chips), режими s60/s120/n20/free.

## Тестування

Інструменти в контейнері: node v22 (`/opt/node22/bin/node`), playwright (глобально,
`/opt/node22/lib/node_modules/playwright`, chromium у `/opt/pw-browsers` →
`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`), статичний сервер. Playwright працює добре; для
сервера надійніше `python3 -m http.server <port> --bind 127.0.0.1` (npx http-server інколи
стартує повільно). Проксі для Харизми мокати через `page.route(/corsproxy|allorigins|thingproxy/)`.
Зовнішня мережа ЗАКРИТА — Google Fonts і Вікіпедія не вантажаться (Вікіпедію мокати через
`page.route`; шрифти — фолбек у скриншотах).

Схема перед пушем:
1. `node --check` на кожен змінений js-файл.
2. Playwright: підняти http-server, проклацати модуль, перевірити стан стора і відсутність
   pageerror. Кирилицю вводити через `dispatchEvent(new KeyboardEvent('keydown',{key}))`, НЕ
   keyboard.type. Записи інжектити в `App.store.state.records.*` + `App.store.save()`; навігація
   через `location.hash` (без reload). Кліки, перекриті оверлеєм Шульте, робити in-page через
   `element.click()` у `page.evaluate`.
3. Тестові скрипти — у /tmp (ефемерні), писати заново.

Примітка про дивний `pkill`/фонові процеси: інколи команда з `pkill -f "http-server"` віддає
exit 144 і рве послідовність — НЕ використовуй pkill; просто перевір порт curl'ом і за потреби
підніми сервер на новому порту.
